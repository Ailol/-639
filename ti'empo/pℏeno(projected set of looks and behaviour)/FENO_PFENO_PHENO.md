# feno → pfeno → pheno

Ailo's definition (2026-09-29) is a transformation of data into a trait:

| Stage | Meaning | Sorting question |
| --- | --- | --- |
| **feno** | Hardware or inward data | What is present inside the device, body, or data structure? |
| **pfeno** | The **pfazing** between something being usable and understanding its use | What operation, test, or interpretation makes the inward material usable, and how is that use understood? |
| **pheno** | A presentable set of data shaped into a trait | What can be shown as an articulated characteristic or behavior? |

```text
feno (hardware / inward data)
  → pfeno (usable ↔ understanding its use)
  → pheno (presentable data → trait)
```

The middle is a phase, not merely a different spelling of an input or a finished display. It can feed understanding back into the inward data and alter what is presented.

## How this changes the tree

The existing `pℏeno(projected set of looks and behaviour)` names the outward projection. Its nested `feno(adapt'n'solv for use)(dev)` branch can still hold inward/dev material. Folder depth does not itself assert causal order; this page supplies the reading order. Place a new item by the role it currently plays, and record its move through the stages when it changes role.

For example, a stored graph or device reading may be feno; parsing, validation, simulation, and discovering how to apply it may be pfeno; a documented, inspectable trait may be pheno. That is an example of classification, not a claim that every BioChain output is a biological trait.

This definition came from Ailo's clarification, not from the linked repositories. Preserve `pfeno` as its own stage when mapping q'partikles, Cypher, BioChain, and the Atomic Inscribe.
